## 1. Starting from nothing on a new machine

```bash
git clone https://github.com/alisid0/QUBIX_UNI-.git
cd QUBIX_UNI-
npm ci                     # package-lock.json is committed; use ci, not install
npm run data               # rebuild all 54 tables, about eight seconds
npm run check:dataset      # 86 assertions, should print "all checks pass"
npm run dev
```

Node 20.10 or newer. `.nvmrc` pins 22.17.0, which is what this was built on, and
`package.json` declares the floor.

That sequence was run for real on a clean clone of `f9c8bba` before this document
was written: `npm ci` succeeded, `npm run data` produced all 54 tables, and
`npm run check:dataset` printed *all checks pass, 7,205,895 rows inspected*.

Copy `.env.example` to `.env.local` and fill it in if you need Supabase. The app
runs without it for everything in this handover; the dataset work touches no
network and no keys.

`STATE.json` is gitignored and regenerated by `npm run state`. `STATE.md` is the
committed version. Do not go looking for `STATE.json` in the repo.

**You do not need to download anything to have the data.** `npm run data`
reproduces all 54 tables byte for byte, because the generator is seeded. The
360 MB is not in git and never will be; see section 4.

## 3. The traps that cost me time

**Heredocs mangle escaping, and they do it silently.** Three separate attempts
at patching `check-dataset.mjs` through a bash heredoc failed: one with
`unexpected EOF`, two with anchors that looked byte-identical to the file and
were not. Use the Edit tool, or write a `.mjs` file and run it. Do not pipe a
patch script through bash unless you enjoy this.

**Backticks inside a double-quoted bash string are command substitution.** I
built the GitHub release notes with a `node -e "..."` containing markdown code
fences. Bash executed the fences. The release published with its code blocks
eaten, and the shell tried to run `data/README.md` line by line. Write the file
with a tool, then point `gh` at it.

**Python's `write_text` converts LF to CRLF on Windows.** A patch script rewrote
`check-dataset.mjs` from LF to CRLF, which silently broke every later anchor
match. If you must patch with Python, read bytes, detect the ending, normalise,
patch, and write the original ending back.

**GNU tar reads `C:/Users/...` as a remote host called `C`.** It tries to ssh to
it and fails with "cannot connect". `--force-local` fixes it, and
`scripts/pack-data.mjs` already passes it.

**Git Bash `/tmp` is not Node's `/tmp` on Windows.** Extracting to `/tmp` and
then reading it from Node gives `ENOENT: C:\tmp\...`. Use the scratchpad path.

**`git push -q` hides failures as effectively as it hides success.** Verify with
`git rev-parse origin/main` rather than trusting a quiet exit.

**`data/` is gitignored, so it goes stale without telling you.** A smoke test run
with `--branches 6` or `--days 7` leaves a partial estate sitting there under
exactly the right filenames, and nothing about it looks wrong. Mine had drifted
back to a six-branch, 151,267-sale build and I only found out by comparing
against a fresh clone.

`scripts/pack-data.mjs` now counts the estate and refuses to pack anything that
is not 48 branches. Run `npm run data` before you trust `data/` for anything that
leaves your machine.

**The generator really is deterministic across machines.** Verified by cloning
from GitHub onto a clean tree, running `npm run data`, and hashing all 54 tables
against a local rebuild: 54 of 54 byte-identical. If yours differ, your `data/`
is stale, not the generator.

## 4. Why the data is not in git, and do not try again

`sale_line.csv` is 187 MB. **GitHub refuses any file over 100 MB outright** and
the push fails; this is not a preference.

Even if it fit: the generator is seeded, so changing one parameter shifts every
downstream byte, and regenerated CSVs do not delta against their old selves.
Each rebuild would add most of 360 MB to history permanently, on a public repo,
for data a command reproduces exactly in eight seconds. Git LFS does not help
either, since the free tier is 1 GB and this is 360 MB a version.

The two supported routes are `npm run data` and the release archive. Both give
byte-identical files.

## 5. The lesson that generalises

**A fault present on every row is not a fault, it is the format.**

This bit twice in one session and both times the guard caught what no eyeball
would have:

- Every basket in the chain ended with a weighed item, because closing on the
  scales was how I made totals balance. The tell was that the weighed-line count
  was exactly the sale count.
- `good + scrap` failed to reconcile against `planned` on 827 of 827 production
  runs.

Both now sit at realistic minorities (10% of lines weighed, 210 of 855 runs
short), and both have guards asserting they stay a minority. When you add a
deliberate fault, add the assertion that it has not become universal.

The corollary: a deliberate fault must not sit behind a coin flip either. The
three mid-quarter tariff changes are always emitted, because a guard cannot
assert something that is only usually there.
